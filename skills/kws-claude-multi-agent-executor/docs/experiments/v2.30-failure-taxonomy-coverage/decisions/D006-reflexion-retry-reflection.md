# D006 — J7 Reflexion structured retry reflection: design, fixture-eval gated (P2)

**Date**: 2026-06-08
**Status**: Designed — not implemented this round (P2 design-only, fixture-eval gated)

## Context

On a retry, the re-dispatch prompt injects `## Fix Required {issues}` (the latest
review's findings) but does NOT give the implementer the *cumulative* context of why
prior attempts failed. v2.29 I3 already records that history in per-plan
`retry_trace[]` (`{attempt, fault, recurring_keys, tier}`). Reflexion (Shinn et al.
2023) shows that converting failures into explicit verbal guidance improves retry
success. The data exists; it is just not consumed.

## Options considered

- **A — No change.** Retries keep repeating faults the trace already names.
- **B — Inject a `## Previous attempts and why they failed` block** built from
  `retry_trace[]`, in addition to the existing `## Fix Required`. Data is consumed,
  no new state. The block is generated by a helper (`build_context_slice.py`, v2.29
  I5, or a small new helper) so the orchestrator never accumulates the trace
  in-context.
- **C — Larger redesign of the retry loop.** Out of scope; B is the minimal,
  data-reuse change.

## Analysis

B is low-surface but it edits orchestrator/implementer **prompts**, which Anthropic
warns can change sub-agent behavior unpredictably. So per plan principle 4 it must
be **fixture-eval gated** before adoption: pass fixture 06 (flaky-test-recovery) +
a new "repeated-fault" fixture that fails unless the cumulative context is used,
with a before/after comparison and an experiment record. The change touches
`references/phases/phase-1-task-cycle.md` (retry prompt builder) and
`references/implementer-prompt.md` (consume the new block).

## Decision

Record the design + the gate. Implement in a v2.30.2 pass: (1) add the repeated-fault
fixture, (2) wire the `retry_trace`-derived block via a helper (no in-context
accumulation), (3) before/after fixture eval must show fewer repeated faults, (4)
experiment record. No prompt edits this round.

## Consequences

- When built, retries get cumulative failure context for free (data already
  recorded by I3) — a Reflexion-style improvement with no new state.
- Gated so an emergent prompt-behavior regression can't ship silently.

## Open questions

- Whether the repeated-fault signal is measurable deterministically (rubric) or
  needs the judge. Prefer a deterministic rubric (count of recurring `fault` keys
  across attempts) to avoid judge variance.
