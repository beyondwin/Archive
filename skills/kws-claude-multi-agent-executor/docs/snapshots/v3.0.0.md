## Architecture pivot

v2.x carried the freeze-skip regression class: the orchestrator LLM read prose
transition rules and could silently skip steps, miscalculate retries, or forget
record-keeping emits, leaving `state.json` wrong in ways no eval could detect.

v3.0 moves the judgment layer into a deterministic Python kernel:

```
loop:
  action = python3 kernel.py next --state <path>
  perform the action exactly as the §④ table dictates
  if dispatch:
      python3 kernel.py submit --state <path> --task <id> --role <role> --result <path>
  # repeat until finalize returns {"status":"finalized"}
```

The orchestrator **runs** the kernel and **performs** the returned action. It does
NOT decide transitions, compute review tiers, count retries, or append quality_trend.

## Kernel modules (14)

11 core execution/transition modules + 3 auxiliary modules (excluding CLI entry point `kernel.py`):

| Module | Responsibility |
|--------|----------------|
| `statefile.py` | Atomic state I/O (flock + temp + rename). Single-writer contract. |
| `planparse.py` | `parse(plan_text)` → task list + structural-validation errors. |
| `gate.py` | `assign_risk`, `partition_waves`, `preflight` (single dispatch-decision source). |
| `packets.py` | `build_packet` → per-task prompt packet in `<orch_dir>/packets/`. |
| `transitions.py` | `decide(state)` + `apply_result(state, task, role, result)` — pure functions. |
| `dispatch.py` | `build(state, action)` — assembles full dispatch materials (command, prompt_path, schema_path, result_path, transport, model). |
| `ledger.py` | `record(state, task, role, usage)` + `extract_payload(text)` — cost/usage accumulation. |
| `events.py` | `emit(orch_dir, event_type, payload)` → `<orch_dir>/events.jsonl` (append-only). |
| `recovery.py` | Escalation resolution, reset directives, drift-repair guidance. |
| `drift.py` | `check(state)` → blocking/non-blocking drift signals for finalize. |
| `quality.py` | `build_run_quality(state)` + `build_completion_audit(state)` for finalize output. |
| `initcmd.py` | `kernel.py init` implementation — arg parsing, worktree+branch creation, 4 hooks materialize, state.json initialization. |
| `migrate.py` | v2→v3 state migration (schema_version:2 → 3). Preserves plan_chain and all per-task fields. |
| `validate.py` | Result schema validation for `submit` + v3 canonical state checks (replaces v2 `validate_state_schema.py`). |

## State schema v3

`schema_version: 3` is the single canonical value. Key structural changes from v2:

| Field | v3 shape | Notes |
|-------|----------|-------|
| `status` | `"SETUP"` / `"RUNNING"` / `"FINALIZED"` | `SETUP` is new (init-to-first-next gap) |
| `execution_plan` | `list[list[str]]` | Exact shape `decide()` iterates; a list-of-dicts silently breaks dispatch |
| `tasks` | Per-task: `status`, `risk`, `files`, `review_retries`, `verifier_retries`, `escalation_count`, `spec_score`, `quality_score`, `review_tier`, `timing`, `pre_task_sha` | `timing.started` stamped by `next` set-if-absent; `timing.completed` at terminal |
| `cost_ledger` | `{"dispatches": N, "by_role": {…}, "totals": {…}}` | Accumulated per `submit` by `ledger.record` |
| `run_quality` | `{"grade", "pass_rate", "warn_rate", "skip_rate", "spec_score_mean", "quality_score_mean"}` | Written by `finalize` |
| `completion_audit` | `{"total_tasks", "complete", "skipped", "verification_gaps", "method_audit_warnings"}` | Written by `finalize` |

Migration bridge (`migrate.py`) translates v2 `schema_version:2` state to v3 shape
transparently, preserving `plan_chain` multi-plan state and all per-task fields.

## Kernel CLI subcommands

| Subcommand | Purpose | Exit codes |
|------------|---------|------------|
| `init` | Parse args, create worktree+branch, materialize 4 hooks, write initial state | 0=ok, 2=halt (dirty_worktree etc.), 3=error |
| `next` | `decide(state)` → next action JSON + dispatch materials | 0=ok, 3=error |
| `submit` | Parse result, validate schema, `apply_result`, record cost, emit event | 0=ok (accepted or rejected), 3=error |
| `check-stop` | Stop-hook entrypoint: block if PENDING_BATCH or finalize-pending | 0=allow, 2=block |
| `finalize` | `drift.check` → stamp `completed_at` → `run_quality`+`completion_audit` → `status:FINALIZED` | 0=ok, 3=blocking drift |
| `inspect` | Diagnostic read of state.json → human-readable summary | 0=ok |
| `resolve-escalation` | Clear `pending_escalation`, record answer to `escalations_resolved` | 0=ok, 3=error |

## Stop hook — kernel.py check-stop

The `Stop` hook in `<worktree>/.claude/settings.json` runs:
```
python3 <skill_dir>/scripts/kernel/kernel.py check-stop --state <state_path>
```

This replaces the v2.26 `finalization-stop-gate.sh` prose gate. Responses:

| Signal | Exit | Meaning |
|--------|------|---------|
| `all_tasks_terminal_finalize_pending` | 2 (BLOCK) | Run `kernel.py finalize` |
| `batch_drain_pending` | 2 (BLOCK) | Run `kernel.py next` (batch verifier), then finalize |
| `already_finalized` | 0 (ALLOW) | Nothing to block |
| `not_ready` | 0 (ALLOW) | Tasks still in progress |
