## New state fields

- `cost_tracking_waive_reason` (run-level, optional, default null) — records why the
  cost waive fired; set to `"agent-dispatch-no-usage"` by the D001 auto-waive.
  Rendered in the Final Summary as `Cost tracking: WAIVED — {reason}`. Run-level and
  preserved across every resume / chain handoff.
- (`cost_tracking_waived` carried over from v2.26/v2.27; now also set automatically by
  the D001 auto-waive rather than only by hand.)

## New finalize / schema signals at ship time

- `timing_inverted` — **un-waivable** blocking FAIL: `completed < started` on the same
  task is corruption, not absent data, so there is no waive escape hatch.
- `quality_trend_sparse` — WARN: a multi-task run whose `<active>.quality_trend` buffer
  is empty/short relative to completed reviewed tasks. Docs-only tasks without review
  are excluded from the denominator.
- `agentlens_run_absent` — WARN: no `agentlens_orchestration_run` id recorded on a
  non-degenerate run.
- `task_key_noncanonical` — WARN: a task key not matching `TASK_KEY_RE`.

## Honest limitation carried forward

The auto-waive only fires when no `api`/`p` gate is set AND mode is attached — any
metered gate disables it — and is rendered loudly, so it is reasoned and discoverable
rather than silent; but it does hide cost on a run the user *did* want tracked under a
metered gate they forgot to set. `timing_inverted` requires `started > completed` on
the same task (one monotonic clock), so sub-second skew cannot trip it. The
all-terminal Stop trigger intentionally blocks a user who paused after the last task
(finalize is mandatory; stderr prints the `--fix` command). A run that skips Phase 2
**and** disables the Stop hook still bypasses everything — that "ignore the skill
entirely" path is outside what any in-band mechanism can catch (the v2.27 D003
`hooks_not_wired` finalize backstop covers the wired-but-unhooked case).
