# Changelog

User-visible changes to the kws-claude-multi-agent-executor skill.

## v2.29.0

Quality uplift — 12 items (I1–I12) on three axes (context reduction, autonomous
handling, observability). All additive; `schema_version` unchanged.

### Changed

- **No more last hard stop in Phase 1 (I1):** review/verifier retry-cap exhaustion now SKIPs the task (recording a `verification_gaps` entry + a `blocker` event) and continues, instead of halting for manual intervention. The verifier branch resets to `pre_task_sha` before SKIP so the tree stays clean.
- **Spec re-read after an edit is now partial (I6):** only the changed `spec_manifest` sections are re-read (regenerating the manifest on a structural edit), not the whole spec.
- **WARN + HIGH-risk + quality_score < 0.70 → one forced Verifier pass (I9):** a PASS promotes the tier WARN→PASS; bounded to fire at most once per task.
- **Run reports are now machine-readable (I4/I7):** Phase 2 emits `<orch_dir>/run_report.json` (schema `run_report/1`, incl. a `failure_summary` roll-up) alongside the markdown, generated by `build_final_report.py` rather than hand-aggregated.

### Added

- **Local `events.jsonl` timeline (I2):** every boundary emit is teed to `<orch_dir>/events.jsonl` regardless of AgentLens reachability — the all-agent attached default now always leaves a replayable timeline.
- **Per-task `retry_trace` (I3):** append-only record of why each retry happened.
- **Helpers:** `build_final_report.py`, `build_context_slice.py` (I5), `state_resume_digest.py` (I10); `phase_boundary.py` gains `emit` + `retry-trace` subcommands.
- **`auto_resolved_count` (I8):** run-level tally of autonomous reinterpretations, surfaced at compaction over a threshold (observation only).

### Internal

- Resume / chain handoff boots from `state_resume_digest.py` instead of the full state.json (I10); T3 compaction discipline made explicit — keep_first pin + prior tool-result drop (I11). I12 (native Agent SDK context-editing) recorded as deferred (D001).

## v2.25.0

### Changed

- Added a third dispatch transport `"agent"` and made it the **default for all role gates** (Plan Reviewer, Verifier, Transition, Docs Updater, final sweep). `"agent"` dispatches the role in-session via the Agent tool on the **subscription pool** (Max/Pro), not metered API credits — a bare invocation now runs every role on the subscription with `$0` metered spend. Metered transports remain available by explicitly setting a gate to `"api"` or `"p"`.
- Plan Reviewer now runs on **Opus** (`claude-opus-4-8`) by default (was Haiku 4.5).
- Autonomous failure ladder (per D003): on a recoverable dispatch failure the orchestrator retries once, then falls back to `"api"` for that single dispatch, then records a gap marker and continues — it **never prompts the user**.
- Per-plan `verification_gaps` / `docs_gaps` fields are recorded in state and surfaced prominently in the Final Summary Report.

### Breaking / UX

- Under `detach=true`, agent-default gates (not explicitly set) fall back to `"api"` with a one-line warning (per D002), so the subscription default never causes surprise metering on a headless parent. Explicit `"agent"` gates are respected.

## v2.22.0

### Changed

- Headless dispatch (Plan Reviewer, Verifier, Transition, Docs Updater) now goes through the Anthropic Messages API with prompt caching instead of `claude -p`.
- Plan Reviewer runs on Haiku 4.5.
- Phase Transition T1 (batch Verifier) and T2 (Phase Docs Updater) merged into one combined dispatch.
- Phase 2 Step 0 final LOW sweep can use the Message Batches API (`dispatch_config.final_sweep`).

### Breaking / UX

- Bare invocation now runs attached in-session by default; pass `detach=true` for the previous headless self-spawn behavior (2-week deprecation warning during transition).
