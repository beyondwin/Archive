## 0. 한 줄 요약

이 스킬은 **이미** 업계·공식 멀티에이전트 모범사례 대부분을 구현하고 있다(§2.1).
따라서 v2.30 은 "기능을 더 얹는" 라운드가 **아니라**, 세 방향으로 *검증 가능한
가치*만 더한다:

- **축 D — 검증 커버리지 (eval 레이어)**: MAST 14개 실패모드를 현 픽스처/가드레일에
  매핑해 **미커버 고빈도 클래스**(리뷰어 고무도장, 오류 전파)에 픽스처를 추가하고
  judge 편향을 하드닝. SKILL.md 와 직교 출하 → **최저 회귀 위험**.
- **축 E — 데이터 기반 선반 재방문 (방법론)**: v2.29 가 `run_report.json` +
  `events.jsonl` + `failure_summary` 를 출하해 코퍼스가 풍부해졌다. `deferred-
  candidates.md` 의 *명시적 트리거*(Haiku 티어링, context_health 능동관리, plan
  pre-mortem)를 **추측이 아니라 실측 분포**로 평가한다. 일부는 "여전히 skip" 결론
  가능.
- **축 F — 신규 자율/검증 거동 (오케스트레이터)**: 아직 미출하·미선반인 거동만.
  Reflexion식 구조화 성찰을 retry 에, AC 결바 반-고무도장 교차검증을 리뷰어에,
  실패 시 플랜-DAG 재계획 결정점을. **회귀 위험 높음 → 각각 fixture eval 게이팅.**

세 축은 v2.29 의 A/B/C(컨텍스트·자율·로그)를 잇되, 이번엔 **"우리가 실제로 못 잡는
실패는 무엇인가"** 를 MAST 렌즈로 먼저 묻는다.

## 1. 분석 방법 (어떻게 도출했나)

두 서브에이전트를 병렬로 돌려 다각도로 분석했다.

1. **Claude Code / Agent SDK 역량 심층 조사** — sub-agent(병렬/격리/모델선택/결과반환),
   Agent SDK(세션 resume, headless `-p` vs interactive, 프롬프트 캐시 TTL), hooks
   (PreToolUse/PostToolUse/SessionStart/Stop/SubagentStop), worktree 네이티브 격리,
   plan-mode/permission-mode, **알려진 한계**(서브에이전트 중첩 불가, 컨텍스트 비공유,
   headless 캐시 손실)를 문서 URL 기준으로 확인.
2. **업계·연구 멀티에이전트 패턴 서베이** — 토폴로지(orchestrator-worker,
   plan-and-execute, LLMCompiler DAG, supervisor), 검증/자기수정 루프(Reflexion,
   Self-Refine, LLM-as-judge, generate-test-repair), 플랜 분해/재계획, 상태/메모리
   관리, 비용 라우팅(RouteLLM/FrugalGPT), 관측/실패처리, 그리고 **MAST 실패 분류
   체계**(1,642 트레이스 주석, 14개 실패모드)를 1차 소스 기준으로 수집.

### 2.2 MAST 실패-분류 커버리지 매트릭스 (이번 라운드의 핵심 렌즈)

MAST 는 멀티에이전트 시스템 실패를 14개 모드 / 3개 범주로 분류하고, 실패의
**~42% 스펙·설계 / ~37% 에이전트간 조정 / ~21% 검증·종료**로 보고한다. 현 픽스처
8개 + 가드레일에 매핑하면:

| MAST 범주 | 실패모드 | 현 커버 | 갭 |
|-----------|----------|---------|----|
| 1. 스펙·설계 | FM-1.1 태스크 스펙 불복 | 픽스처 08(메타룰), Reviewer Spec Walk(v2.9) | — |
| | FM-1.2 역할 스펙 불복 | "Orchestrator never writes code" 가드레일, SubagentStop 훅 | — |
| | FM-1.3 단계 반복 | (없음) | **resume 후 완료 태스크 재실행 프로브 없음** |
| | FM-1.4 대화 히스토리 손실 | 픽스처 04(cross-plan), Resume Chain, state.json 진실원 | 약 |
| | FM-1.5 종료 조건 미인지 | Stop-훅 강제(v2.26–28), finalize_run | — (단 eval 미직접검증) |
| 2. 에이전트간 | FM-2.1 대화 리셋 | 픽스처 04 | — |
| | FM-2.2 명확화 요청 실패 | 픽스처 05(ambiguous-spec, expected-halt), Ambiguity Gate | — |
| | FM-2.3 태스크 이탈 | Files-block 부분집합 검증(병렬), 보호파일 체크 | 약 |
| | FM-2.4 정보 은폐 | 구조화 출력 계약(STATUS/SUMMARY/FILES) | — |
| | FM-2.5 타 에이전트 입력 무시 | `previous_issues` 주입, decisions_register | — |
| | FM-2.6 추론-행동 불일치 | Method Audit(v2.11, RED/GREEN 증거) | — |
| 3. 검증·종료 | FM-3.1 조기 종료 | Stop-훅, polite-stop 금지 가드레일(v2.10.1) | — |
| | FM-3.2 미/불완전 검증 | Verifier 전체스위트, LOW 배치 sweep | — |
| | FM-3.3 **부정확 검증(고무도장)** | 픽스처 08(적대 입력), Spec Walk | **테스트는 통과하나 스펙 의도 위반 케이스 미커버** |

**→ 이번 라운드의 표적 갭(고가치 순):**
1. **FM-3.3 리뷰어 고무도장** — 코드가 *기존 테스트는 통과*하지만 스펙이 요구하는
   (테스트로 안 덮인) 거동을 위반하는 케이스. MAST 가 명명한 "review processes
   rubber-stamping" 안티패턴. 현 픽스처 08 은 *적대적 입력*을 리뷰어가 잡는지를 보는
   것이고, 고무도장 프로브(green build + wrong behavior)는 별개. **커버 0.**
2. **오류 전파를 사실로 취급** — 태스크 N 의 잠복 결함이 태스크 N+1 의 입력으로
   들어가 증폭. 현 픽스처에 다단 전파 체인 없음. **커버 0.**
3. **FM-1.3 단계 반복** — resume/압축 후 완료 태스크를 재실행하는지. 약함.
4. **judge 편향** — `judge.md` 가 위치/장황함/자기선호 편향 가드 없음(리서치: LLM
   judge 의 알려진 병리). eval 신뢰도 직접 영향.

### 2.3 v2.29 가 새로 연 데이터 (축 E 의 전제)

v2.29 가 `run_report.json`(schema `run_report/1`) + `events.jsonl` tee +
`failure_summary` 를 출하했다. v2.24 가 35-run 코퍼스 베이스라인을 이미 떴다

## 3. 설계 원칙 (재설계의 앵커)

v2.29 원칙(컨텍스트 희소자원, sub-agent=장황 격리, 외부 메모리, just-in-time,
실패-알림-적응, end-state 구동, 구조화 트레이스, 휴리스틱+가드레일)을 계승하고
**이번 라운드 추가 원칙**:

1. **"못 잡는 실패"부터 측정** — 기능 추가 전에 MAST 렌즈로 미커버 실패모드를
   픽스처로 고정. 픽스처는 SKILL.md 와 직교 출하(AGENTS.md) → 회귀 위험 0 에 가깝다.
2. **오라클이 LLM 의견에 선행** — 검증 신뢰는 컴파일러/테스트/AC-shell 같은 oracle 에
   접지될 때만 성립. 리뷰어 "approve"는 oracle 통과 *후에만* 가치. (MAST 21% 검증
   버킷 + 고무도장 안티패턴.)
3. **추측성 임계값 금지(Goodhart 가드 강화)** — 새 임계값·티어링은 `deferred-
   candidates.md` 트리거가 **실측으로 충족될 때만**. 충족 안 되면 데이터와 함께
   "여전히 skip" 을 기록.
4. **오케스트레이터 프롬프트 변경은 fixture eval 게이팅** — Anthropic 경고("lead
   프롬프트 작은 변경이 sub-agent 거동을 예측불가하게 바꾼다"). 축 F 전 항목은
   채택 전 fixture eval 통과를 DoD 로.

- **비용 vs 품질.** 추가 검증 패스(J8)·재계획(J9)은 "고가치일 때만" 조건부 게이팅.

## 4. 개선 항목 카탈로그 (J1–J9)

각 항목: **문제 → 제안 → 축 → 영향/노력 → 근거**. P0(축 D)의 구체 구현은 짝 문서.

### P0 — 축 D: MAST 검증 커버리지 (eval 레이어, 최저 위험)

**J1. MAST 커버리지 매트릭스 문서 + 갭 분석 [축 D]**
- 문제: 픽스처가 어떤 실패모드를 커버하는지 명시 매핑이 없다. 새 픽스처를 추측으로
  추가하면 중복/누락.
- 제안: `docs/eval-coverage-mast.md`(신규) — §2.2 매트릭스를 권위 문서화. 각 픽스처에
  `mast_coverage: [FM-x.y]` 메타 주석(픽스처 YAML 또는 매트릭스 표)을 부여. 갭 목록과
  재방문 트리거를 명시.
- 영향: 中(방향 고정) / 노력: 低. 근거: §2.2; ARCHITECTURE §10.

**J2. 리뷰어 고무도장 프로브 픽스처 `09-spec-intent-uncovered.yaml` [축 D]**
- 문제: 코드가 *기존 테스트는 통과*하지만 스펙이 요구하는(테스트 미커버) 거동을
  위반하는 케이스를 우리 파이프라인이 잡는지 측정된 적 없음. MAST FM-3.3.
- 제안: 부트스트랩 레포에 "통과하지만 불완전한" 테스트를 심고, 스펙은 추가 거동을
  요구. 기대 결과: Combined Reviewer 의 Spec Coverage Walk(v2.9)가 미커버 스펙 불릿을
  `NOT FOUND`/`PARTIAL` 로 표면화(WARN/FAIL) **또는** AC-shell 이 미커버 거동을 잡음.
  expected-halt 가 아니라 *검출-후-수정* 픽스처.
- 영향: 高(21% 검증 버킷 핵심) / 노력: 中. 근거: 픽스처 08 와 다른 축;
  reviewer-prompt.md Spec Walk.

**J3. 오류 전파 체인 픽스처 `10-error-propagation.yaml` [축 D]**
- 문제: 태스크 N 의 잠복 결함이 N+1 입력으로 전파되는지 미측정. MAST 명명 안티패턴.
- 제안: 2-태스크 플랜. 태스크 1 이 공유 모듈에 잠복 결함을 도입(겉보기 통과), 태스크 2
  가 그 모듈에 의존. 기대 결과: 태스크 1 의 per-task Verifier(MID/HIGH)가 전파 *전에*
  결함을 잡거나, 배치 sweep + 최종 verify 가 잡아 **silent ship 되지 않음**. 픽스처는
  "결함이 최종 산출물에 남지 않음"을 rubric 으로 단언.
- 영향: 高(37% 조정 버킷의 핵심 표현) / 노력: 中. 근거: §2.2; Verifier baseline 비교.

**J4. `judge.md` 편향 하드닝 [축 D]**
- 문제: LLM-judge 는 위치/장황함/자기선호 편향이 알려져 있는데 현 프롬프트에 가드가
  없다. eval 신뢰도(특히 code_quality 축)에 직접 영향.
