## v2.26 finalization + schema enforcement

The headline problem: two real `interactive_attached` runs on 2026-06-04 completed
every task but ended with `state.json` unfinalized / non-canonical, because attached
mode had **no forcing function** and Phase 2 finalization was simply skipped.

| Artifact | Role |
|----------|------|
| `scripts/validate_state_schema.py` | Canonical-shape gate (check-only). Flags empty `tasks{}` when declared, `execution_order` without `execution_plan`, risk ∉ low/mid/high, invalid `mode`, missing run-level `dispatch_config`/`cost_ledger`. Exit 0/1/2. |
| `scripts/finalize_run.py` | Finalization gate (`--check`/`--fix`). Flags null `completed_at` (FAIL, fixable), `PENDING_BATCH` (FAIL, unfixable), non-terminal status, dispatches 0 + missing `timing.started` (WARN, suppressed by `cost_tracking_waived`). `--fix` stamps only `completed_at` (atomic); never clears `PENDING_BATCH`. |
| `references/hooks/finalization-stop-gate.sh.template` | `Stop`-hook forcing function (D001). Materialized at Phase 0 Step 2.5; wired into `<worktree>/.claude/settings.json`. |

### Gate wiring at ship time

| Site | Gate |
|------|------|
| Phase 2 Step 1.5 | `validate_state_schema.py` — schema violation → HALT before run-close |
| Phase 2 Step 2 | `finalize_run.py --fix` — unfixable FAIL → HALT before run-close |
| `Stop` hook (session end) | both validators, but only once every task is terminal AND a real end-signal fired → exit 2 blocks the stop if done-but-unfinalized or non-canonical |

The Stop hook resolves the two remaining risks the Phase-2-only gates could not
catch: a run that **never enters Phase 2** (the source-matching failure) and
attached-mode schema improvisation. Cheap single-`jq` short-circuit while any task is
non-terminal keeps per-turn cost negligible. Fail-open on hook-internal error (missing
args/tools/state, validator exit 2); fail-closed on detected inconsistency.

## The four worktree hooks at ship time

`<worktree>/.claude/settings.json` wires four hooks, all referencing absolute paths
under `<orch_dir>/hooks/` (outside any worktree):

| Event | Script | Purpose |
|-------|--------|---------|
| `PreToolUse` (Bash) | inline guard | block `rm -rf /`, force-push to protected branch, `DROP TABLE/DATABASE/SCHEMA` |
| `PostToolUse` (Edit\|Write) | `scan-debug-artifacts.sh` | debug-artifact gate |
| `SubagentStop` | `check-implementer-output.sh` | Implementer output-structure validator |
| `Stop` | `finalization-stop-gate.sh <state.json> <scripts>` | finalization forcing function (v2.26) |

## New state field

`cost_tracking_waived` (run-level, optional, default `false`) — suppresses the
`cost_dispatches_zero` WARN for runs where cost tracking is intentionally off.

## `mode` enum at ship time

`state.mode ∈ {interactive_session, interactive_attached, headless_pending,
headless_running, headless_chained, plan_chain_running, plan2_running}`.
`validate_state_schema.py` enforces this enum (`mode_invalid` violation).
