## New state fields (all additive, default-absent)

- `auto_resolved_count` (run-level int, default 0) — D003 autonomous-reinterpretation tally; T3 surfaces over threshold; observation only (I8).
- `tasks.task_<N>.retry_trace` (per-plan, append-only list) — {attempt, kind, fault, recurring_keys, tier, ts} (I3).
- `tasks.task_<N>.forced_verify` / `forced_verify_outcome` (per-plan) — forced-Verifier dedupe guard + WARN→PASS promotion marker (I9).
- `tasks.task_<N>.skip_reason` (per-plan) — `review_retries_exhausted` / `verifier_retries_exhausted` (I1); `verification_gaps` entries gain `kind`/`last_issues`/`attempts`.

## New artifacts produced per run

- `<orch_dir>/events.jsonl` — append-only boundary-event timeline, orchestrator single writer, present even when AgentLens is dark (I2).
- `<orch_dir>/run_report.json` — machine-readable run report (schema `run_report/1`), the `aggregate_runs.py` input, carrier of `failure_summary` (I4/I7).

## Honest limitations carried forward

- The markdown report's free-form sections (Changes Made / Verification Results / Docs Updated / Remaining Risks) are derived from state signals, not byte-equal to a hand-written narrative — the snapshot test locks structure + derived fields, not prose.
- I9's forced Verifier fires only for HIGH + quality_score < 0.70 (bounded cost, §3.1); a mid-risk low-confidence WARN gets no extra pass.
- I8 / I11 are observation + discipline; neither halts. Native context-editing (I12) remains unreachable until an Agent SDK port (D001).
