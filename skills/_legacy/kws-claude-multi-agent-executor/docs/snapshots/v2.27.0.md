## v2.27 attached-mode enforcement

The headline problem: three real runs on 2026-06-06, all `interactive_attached`
(the v2.22 default), exposed two gaps the v2.26 gates did not close — every action
in attached mode is prose-driven and therefore skippable.

| Gap | Root cause | Closed by |
|-----|------------|-----------|
| Hook-wiring loss | Phase 0 Step 2.5 hand-wrote settings.json with no merge; a repo shipping its own settings.json (`readmates`, a `permissions` allowlist) kept `permissions` but wired **zero** hooks — including the v2.26 Stop gate | D001 |
| Bookkeeping drift | `dispatches==0` and all-null `timing.started` were WARN, so a fully-drifted run (`per-role-confidence`) finished `passed: true` | D002 |
| Skipped-write bootstrap (residual) | Both Step 2.5 and the `--check` preflight are prose; skipping Step 2.5 entirely wires no Stop gate at all | D003 |

### New / changed artifacts at ship time

| Artifact | Role |
|----------|------|
| `scripts/materialize_worktree_hooks.py` (NEW) | Deterministic worktree settings.json writer. `build_hooks`/`merge_settings`/`check_problems`/`do_write`/`do_check`. Deep-merges so every existing top-level key (`permissions`, `$schema`, other hook events) survives and the four events we own win. Self-asserts after write; exit 1 on assertion failure or unparseable existing file. `--check <worktree>` is the reused preflight (D001, improvement #3). |
| `scripts/finalize_run.py` (CHANGED) | `cost_dispatches_zero`: WARN → **FAIL** (suppressed by `cost_tracking_waived`). New aggregate `timing_tracking_absent`: **FAIL** when ≥1 terminal task and every terminal task has null `timing.started` (suppressed by `timing_tracking_waived`); per-task `timing_started_missing` stays WARN for partial misses (D002). New `hooks_not_wired`: **FAIL** when the worktree settings.json is present+parseable but missing the four hooks / Stop gate (suppressed by `hooks_wiring_waived`); skips silently when settings.json is absent/unparseable (D003). |

### Gate wiring at ship time

| Site | Gate |
|------|------|
| Phase 0 Step 2.5 | `materialize_worktree_hooks.py --worktree … --orch-dir … --skill-dir …`; non-zero exit = hard halt (replaces the hand-written JSON block) |
| Phase 1, once before Task 1 | `materialize_worktree_hooks.py --check --worktree …`; non-zero = hard halt |
| Phase 2 Step 1.5 | `validate_state_schema.py` (unchanged from v2.26) |
| Phase 2 Step 2 | `finalize_run.py --fix` — now also surfaces `cost_dispatches_zero` / `timing_tracking_absent` / `hooks_not_wired` as blocking FAIL |
| `Stop` hook (session end) | both validators; the elevated finalize severities now reach through the unchanged v2.26 gate → exit 2 blocks a drifted or unwired finish |

## New state fields

- `timing_tracking_waived` (run-level, optional, default `false`) — suppresses the
  `timing_tracking_absent` FAIL for runs where timing is intentionally untracked.
- `hooks_wiring_waived` (run-level, optional, default `false`) — suppresses the
  `hooks_not_wired` FAIL for contexts where the worktree is intentionally
  absent/uninspectable.
- (`cost_tracking_waived` carried over from v2.26; now suppresses a FAIL, not a WARN.)

## The four worktree hooks at ship time

Unchanged in shape from v2.26 — `PreToolUse` (inline Bash guard), `PostToolUse`
(`scan-debug-artifacts.sh`), `SubagentStop` (`check-implementer-output.sh`), `Stop`
(`finalization-stop-gate.sh <state.json> <scripts>`). The change is *how the block
is written*: `materialize_worktree_hooks.py` deep-merges it into any pre-existing
settings.json instead of clobbering, and the same shape is asserted at write time,
at the Phase-1 preflight, and (for the wired-ness of the result) at finalize time.

## Honest limitation carried forward

At Stop time lost timing/cost data is unrecoverable; the gates force fix-or-waive,
not recovery (D002). D003 shrinks but does not eliminate the bootstrap residual: a
run that skips Step 2.5 **and** the preflight **and** Phase 2 finalize wholesale
still wires nothing — that is "ignore the skill entirely," outside what any in-band
mechanism can catch.
