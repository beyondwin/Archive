# CPE 1.3.0 Release Design

## Goal

Publish CPE 1.3.0 as the lean-quality release, close the two remaining direct
test-evidence gaps, restore comfortable deterministic-eval headroom, and make
the released skill immediately discoverable by fresh Codex and Claude Code
sessions through the repository-backed local installation.

## Current State

- `main` is at `b89caf1b5e9309218bd49e573e8df431a91fe8e0` and contains the
  approved lean-quality implementation.
- CPE reports version `1.2.0`.
- The last accepted full gate passed 40 tests in 14.62 seconds. This satisfies
  the hard 15-second ceiling but leaves only 0.38 seconds of headroom.
- Whole-branch review reported no Critical or Important findings. Two Minor
  evidence gaps remain: direct invalid-recovery-field coverage (`T3-003`) and
  direct two-pipe timeout/exception-drain coverage (`T4-M2`).
- `~/.codex/skills/kws-codex-plan-executor` and
  `~/.claude/skills/kws-codex-plan-executor` are symlinks to the tracked skill
  directory, so an in-place repository release is the lowest-drift install.

## Release Scope

### 1. Close residual evidence gaps

Add deterministic focused tests that directly prove:

- any partial combination of `retryable`, `failure_signature`, and
  `next_strategy` is rejected;
- completed results reject recovery fields even when all three are present;
- timeout cleanup drains both registered stdout and stderr streams;
- exceptional launcher exit drains remaining registered streams and closes
  selector and pipe resources.

These are evidence additions for existing safety contracts. Production runtime
behavior changes only if a new test exposes an actual defect.

### 2. Restore eval headroom without weakening coverage

Keep all contract assertions while reducing repeated process setup and fixed
fixture delays. Prefer combining compatible scenarios in one repository/run
fixture and replacing process launches with direct boundary tests only when
the tested contract does not depend on a real process. Preserve real-process
coverage for process groups, advisory locks, coordinator loss, timeout, and
result isolation.

The release gate remains strictly below 15 seconds. The release target is at
or below 12 seconds on the development machine; if the final result is between
12 and 15 seconds after safe consolidation, the release may proceed only when
additional reduction would weaken safety coverage or distort production
semantics.

### 3. Publish 1.3.0 and keep linked installations authoritative

Update the skill metadata and README contract to version `1.3.0`, describe the
new direct safety evidence, and keep the public CLI and format-version-1 state
contract unchanged. Do not add a release tag: this repository has no active
CPE tag convention, and introducing one would create a second release source
of truth. The release is the versioned skill content plus a coherent release
commit on `main`.

The source directory remains the installation source. Validate both local
skill symlinks resolve to that directory and run the standard skill validator.
A fresh-context agent must read the installed skill and correctly report the
1.3.0 version, the `run`/`resume`/`inspect` commands, and the boundary between
CPE and Superpowers. This proves discovery without copying files into a second
mutable installation.

## Compatibility And Safety Constraints

- Preserve public commands `run`, `resume`, and `inspect`.
- Preserve `state.json` `format_version: 1`, plan record fields, historical
  format-1 inspection, immutable input snapshots, clean-HEAD and ancestry
  acceptance, result isolation and `0400` accepted results.
- Preserve one fresh ephemeral Codex process per plan, one shared isolated
  worktree for ordered plans, POSIX process-group cleanup, advisory locking,
  and bounded stderr/usage handling.
- Do not add runtime modules, telemetry, databases, provider cost estimates,
  task mapping, review, fixing, integration ownership, or legacy forbidden
  artifacts and references.
- Keep the tracked CPE inventory at 12 files.
- Do not modify installed Superpowers files or duplicate the linked CPE skill.

## Verification And Release Flow

1. Work in `codex/cpe-1.3.0-release` in an isolated worktree.
2. Capture a fresh-context pre-release discovery baseline.
3. Add focused residual-risk tests and prove their contract checks.
4. Consolidate deterministic fixtures using targeted timing evidence.
5. Update 1.3.0 metadata and documentation.
6. Run the skill validator and a fresh-context release-worktree forward test.
7. Run one final full CPE gate at the final implementation HEAD, followed by
   compile, shell syntax, help, repository hygiene, inventory, and the
   user-supplied forbidden-reference checks.
8. Obtain one whole-branch review. Resolve every Critical or Important finding
   before release.
9. Fast-forward local `main` when unchanged; otherwise integrate without reset
   or force. Verify the tested commit through the installed skill path, then
   push `origin/main`.

## Acceptance Criteria

- Direct tests cover both residual findings and all pass.
- Open Critical, Important, and residual Minor findings are zero.
- The full deterministic suite passes and remains below 15 seconds; at or below
  12 seconds is the release target.
- Skill metadata and README agree on version 1.3.0 and actual behavior.
- Both local skill links resolve to the released tracked directory, validation
  passes, and a fresh-context forward test discovers the release contract.
- The public CLI, format-version-1 compatibility, 12-file inventory, and all
  named safety constraints remain intact.
- The release commit is on clean local `main`, pushed to `origin/main`, with no
  legacy forbidden files, directories, or references.

## Out Of Scope

- A new CPE orchestration architecture or Waygent integration.
- A copied installation, package registry publication, PR, deployment, or new
  release-tag convention.
- Coverage reductions solely to meet the 12-second target.
