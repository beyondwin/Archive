## 1. Decision Summary

The base CPE 2.0 design already addresses the largest observed execution-waste
classes:

- unchanged environment blockers;
- productive versus stalled controller timeouts;
- result-envelope-only retries;
- same-evidence verification replay;
- redundant review lifecycle work;
- unjustified full-context subagent forks;
- missing-usage totals falsely presented as exact.

The new Canvas evidence does not justify another executor redesign. It exposes a
narrower observability gap: CPE can count aggregate input tokens, launches, and
coordination operations, but it cannot yet explain cached versus uncached input,
output and reasoning usage, timeout-related usage darkness, or the byte pressure
of review artifacts.

This addendum therefore makes four decisions:

1. Preserve the accepted Wave 0 and Wave 1 implementation and the in-progress
   Wave 2 contract.
2. Extend Wave 3 with content-free review/context artifact metadata, without
   making CPE a semantic reviewer.
3. Extend Wave 4 reports with field-complete usage, data-quality, and artifact
   pressure summaries.
4. Preserve the current format-1 run as sanitized historical evidence. Do not
   treat it as proof that format-2 behavior has shipped.

## 2. Questions This Addendum Answers

This addendum separates questions that were previously easy to conflate.

1. How many tokens did CPE observe?
2. How many of those input tokens were cache reads rather than uncached input?
3. How much usage is missing because an attempt ended before a final usage event?
4. Which plan and attempt family produced the observed lower bound?
5. Did a file merely exist under `.superpowers/sdd`, or was it declared as
   context for an implementer or reviewer?
6. How large were review packages and diff snapshots?
7. Can root-controller and nested-agent usage be attributed independently?
8. Which observed waste classes are already fixed, being fixed, only planned, or
   still absent from the CPE 2.0 contract?

## 4. Reproducible Collection Method

The following pseudocode describes the aggregation contract. Production tooling
must implement the same per-attempt rules with schema validation and overflow
checks.

```python
finished = [event for event in events
            if event["kind"] == "plan.attempt_finished"]
known = [event for event in finished
         if event["input_tokens"] is not None]

observed_input = sum(event["input_tokens"] for event in known)
observed_cached = sum(event["cached_input_tokens"] or 0 for event in known)
observed_output = sum(event["output_tokens"] or 0 for event in known)
observed_reasoning = sum(event["reasoning_output_tokens"] or 0 for event in known)

# This subtraction is valid only for attempts where both input and cached input
# are present and individually valid.
observed_uncached = sum(
    event["input_tokens"] - event["cached_input_tokens"]
    for event in finished
    if event["input_tokens"] is not None
    and event["cached_input_tokens"] is not None
)
```

The report implementation must not treat a missing cached-input field as zero.
The simplified collection used for this one snapshot was checked against the
events and happened to have cached-input values for every input-known attempt.
Format-2 reporting must retain the stricter paired-observation rule.

Artifact inventory uses `lstat` metadata only. It groups files by stable class
and sums byte length. It does not open diff bodies to estimate tokens.

## 6. Causal Findings

### F1. File existence alone does not consume model tokens

**Source:** derived from the CPE execution boundary.

A file under `.superpowers/sdd` consumes model input only when its content is
included in a prompt, returned by a tool, or otherwise loaded into an agent
context. Counting files or bytes alone cannot attribute tokens.

**Consequence:** reports must use `produced_*` for inventory and
`declared_context_*` for references. They must never label either as
`tokens_consumed`.

### F2. Repeated context dominates the observed input counter

**Source:** derived.

Cached input is 96.3% of the paired observed input. This is consistent with a
controller and nested agents making many calls against mostly repeated context.
It does not identify which documents or messages were repeated.

**Consequence:** CPE must expose cached and uncached input separately and label
the aggregate usage scope.

### F3. Environment and timeout recovery created measurable amplification

**Source:** parent-observed counts plus derived classification.

The run has 15 timeouts. Plan 04 alone has 11. Plan 02 reached 17 attempts and
Plan 04 reached attempt 22. Existing results contain recurring loopback
capability failures.

**Consequence:** the Wave 2 typed capability guard and progress-aware checkpoint
remain the highest-confidence waste controls. This addendum does not add a second
mechanism.

### F4. Review artifacts dominate SDD disk bytes

**Source:** parent-observed filesystem metadata.

Review diff snapshots account for 31.0 MB of 32.4 MB. Several whole-branch diff
snapshots from the same plan boundary are multi-megabyte files.

**Consequence:** Wave 3 must record diff kind, base/head, digest, and bytes. Raw
diff snapshots must not be sealed as durable CPE evidence. Base/head plus a
parent-observed digest are sufficient because the diff can be reconstructed from
Git objects.

### F5. Current usage attribution is aggregate-only

**Source:** parent-observed launcher implementation and documented limitation.

The launcher retains the final `turn.completed.usage`. It may include the root
controller and nested agents. Coordination telemetry can count roles and agent
operations but cannot retroactively split an aggregate token total.

**Consequence:** reports must say
`scope=controller_and_nested_agents_aggregate`. Role attribution remains
`unavailable` unless the provider emits independently attributable usage.

### F6. Timeout attempts create usage-dark intervals

**Source:** parent-observed.

Eighteen finished attempts have no input usage. A killed controller may never emit
the final `turn.completed` event that the current filter expects.

**Consequence:** lower-bound reporting is necessary but insufficient. Reports must
also show unknown attempt duration and missing-usage reasons by plan.

### F7. Test execution and model token usage are different resources

**Source:** architectural boundary.

The test subprocess does not directly consume model tokens. Test output consumes
tokens only when returned to an agent, and debugging consumes tokens through new
model calls.

**Consequence:** reports should separate verification process duration, bounded
output bytes, model usage, and retry cause. They must not infer token cost from
test duration alone.

## 8. Blind Spots And Non-Claims

### B1. No root-versus-subagent token split

The current evidence cannot reconstruct this split. Spawn counts or duration must
not be used as a token allocation formula.

### B2. No proof of artifact reads

`source_context_refs` can prove what the controller declared as context. It cannot
prove the provider ingested every byte or that the model attended to it.

### B3. No exact total when usage is missing

Duration is available for missing-usage attempts, but duration-to-token conversion
would be an estimate. CPE must retain the lower bound and avoid invented totals.

### B4. Cached input is not unique input

`input_tokens - cached_input_tokens` is a paired lower-bound view of uncached
input. It is not a measure of unique documents and must not be named that way.

### B5. Token count is not price

This design does not embed provider prices. Billing rules can change and cached
input may be priced differently. Cost reporting requires a separately versioned
price source and is not part of this addendum.

### B6. Format-1 evidence does not prove format-2 savings

The current run is a baseline and regression source. Only later format-2 runs can
demonstrate launches avoided, verification reuse, or reduced context amplification.

### B7. Artifact thresholds can create perverse incentives

A hard byte cap on reviewer context could hide relevant code. Wave 3 therefore
records payload pressure and emits advisories. It does not reject a semantically
required review solely because the diff is large.

### B8. Deleting artifacts is not the optimization target

Deleting historical files after they have already been read does not recover
tokens. The useful controls are scoped context, canonical artifact reuse, bounded
tool output, and avoiding unnecessary new controller launches.

## 9. Wave 3 Contract Delta

Wave 3 retains its semantic boundary: Superpowers owns reviews; CPE validates and
measures receipts.

### 9.1 Review receipt metadata

Every review receipt must add:

```json
{
  "diff_kind": "task|finding_delta|whole_branch",
  "diff_artifact_digest": "sha256:...",
  "diff_artifact_bytes": 12345,
  "review_package_digest": "sha256:...",
  "review_package_bytes": 23456
}
```

The parent verifies metadata from safe worktree-relative regular files before
acceptance. It stores the digest and byte length, not the raw diff. Duplicate
digests in the same scope become efficiency observations.

### 9.2 Context reference metadata

For each subagent spawn, record content-free declared context metadata:

```json
{
  "context_ref_count": 3,
  "context_ref_bytes": 48192,
  "context_measurement_kind": "declared_refs_not_provider_ingestion",
  "context_classes": {
    "task_brief": 1,
    "review_diff": 1,
    "implementer_report": 1
  }
}
```

Safe context classes are:

- `task_brief`
- `implementer_report`
- `review_package`
- `review_diff`
- `finding_delta`
- `progress_ledger`
- `spec_slice`
- `plan_slice`
- `other_bounded`

Raw content, prompt text, tool output, and absolute source paths remain forbidden.

### 9.3 SDD production inventory

At checkpoint and plan acceptance, CPE records metadata-only inventory for the
owned `.superpowers/sdd` tree:

- files and bytes by stable artifact class;
- largest file bytes;
- review diff count and bytes;
- whole-branch versus delta snapshot count;
- duplicate digest count when already computed for a receipt;
- whether the inventory exceeds sealed-evidence limits.

The inventory is advisory and cannot make a product plan fail by itself.

### 9.4 Usage attribution honesty

Coordination summaries add:

```json
{
  "usage_scope": "controller_and_nested_agents_aggregate",
  "usage_attribution": "unavailable",
  "usage_attribution_unavailable_reason": "provider_event_not_agent_scoped"
}
```

If a later provider event supplies per-agent usage, CPE may record it only with an
agent ID digest and a `parent_observed` source. Child estimates remain
`child_attested` and never alter aggregate totals.

- reject negative or overflowing counters;

- keep launcher prompt bytes in a byte-valued field and never label them tokens;
- never coerce missing usage to zero;
- make aggregate scope and attribution explicit.

### 10.3 Data-quality summary

Wave 4 reports include:

- usage completeness ratio;
- missing usage count and duration by plan/reason;
- coordination telemetry availability;
- declared-context metadata availability;
- artifact inventory availability;
- whether token values aggregate nested agents;
- warnings for inconsistent or partial fields.

### 10.4 Cross-run signal additions

Add candidate categories:

- `usage_darkness`
- `artifact_growth`
- `context_payload_amplification`

Promotion remains conservative:

- `usage_darkness`: two independent runs, or at least three attempts in one run
  with at least 1,800 seconds of unknown-usage duration;
- `artifact_growth`: two independent runs, or at least three checkpoints in one
  run where the produced artifact inventory exceeds the sealed-evidence file or
  byte limit;
- `context_payload_amplification`: two independent runs, or at least three
  same-scope review observations in one run whose declared context bytes increase
  and total at least 8 MiB.

If declared context bytes are unavailable, production bytes alone cannot promote
`context_payload_amplification`.

## 12. Required Tests

### Usage

1. Cached input is preserved independently from input.
2. Uncached input is derived per paired attempt.
3. Missing cached input does not become zero.
4. Cached input greater than input is rejected.
5. Output and reasoning counters are retained.
6. Per-field known/unknown counts may differ.
7. A timeout with no final usage increases unknown duration.
8. Aggregate usage scope is always explicit.
9. Missing per-agent usage produces an unavailable reason.
10. A child-attested role estimate cannot change parent-observed totals.

### Artifacts and context

11. Produced inventory records count and bytes without reading bodies.
12. Symlinks and escaping paths are rejected from declared context refs.
13. Raw diff bodies are not copied into sealed evidence.
14. Review receipts bind diff kind, base/head, digest, and byte length.
15. A repeated same-scope digest is counted as redundant.
16. A finding delta is not collapsed with a whole-branch diff.
17. Unknown declared-context bytes remain `null`.
18. Production-only bytes cannot be reported as model-consumed bytes.
19. Inventory above 128 files or 8 MiB is advisory unless referenced evidence
    itself violates the Wave 1 sealing contract.
20. Artifact telemetry never changes semantic review disposition.

### Historical and reporting

21. The format-1 forensic fixture never enters format-2 success metrics.
22. The fixture remains content-free and path-sanitized.
23. Reports preserve the snapshot's usage lower bound and unknown count.
24. Cross-run analysis cannot promote context amplification without declared
    context evidence.
25. No savings percentage is emitted without before/after format-2 evidence.

## 13. Acceptance Criteria

This addendum is complete when:

- Wave 3 emits bounded artifact/context metadata without storing content;
- Wave 3 distinguishes task, finding-delta, and whole-branch diff observations;
- Wave 4 reports all four launcher usage counters plus paired uncached input;
- every usage field has independent completeness evidence;
- timeout-related usage darkness is visible by count and duration;
- reports state aggregate usage scope and attribution availability;
- produced artifact bytes are never called consumed tokens;
- raw review diffs are not sealed as durable evidence;
- the format-1 Canvas fixture is excluded from format-2 outcome metrics;
- existing Wave 0–2 safety and recovery tests remain unchanged and passing;
- no reviewer, verification, or security gate is removed to reduce tokens.

## 14. Non-Goals

- provider billing or USD estimation;
- raw prompt, transcript, source body, or tool-result persistence;
- probabilistic token allocation across roles;
- deleting CPE-owned worktree artifacts before their receipts are accepted;
- weakening task review, final review, or final verification;
- cross-run verification reuse;
- changing Superpowers upstream skills or plan format;
- reopening accepted Wave 0 or Wave 1 contracts;
- changing the active Wave 2 implementation while it is under review.

## 15. Expected Outcome

After Waves 3 and 4 implement this addendum, an operator can answer:

- how much usage CPE observed and how much is missing;
- how much observed input was cached versus uncached;
- whether the aggregate includes nested agents;
- which plan produced usage-dark timeout duration;
- how many review/context artifacts were produced and declared;
- whether repeated review payloads are growing;
- which savings are directly observed and which remain hypotheses.

The report still will not claim that a specific Markdown file consumed a specific
number of tokens unless the provider exposes that causal evidence. That limit is
intentional.
